# 環境構築・APIキー取得・北海道版移行ノート

作成日: 2026-05-17

このドキュメントは、ローカル開発環境を立ち上げる際に必要なAPIキーの取得手順と、
本リポジトリを「福岡市版」から「北海道版」へ移行していく方針をまとめたもの。

---

## 1. .env と必要な環境変数

ローカル起動には以下が必要。

```bash
cp .env.example .env
```

`.env.example` のうち、ローカルSupabaseのキー・URLはデモ値が既に入っているため
そのまま動く。外部サービス連携系の項目だけ別途取得が必要。

### 1.1 AI_GATEWAY_API_KEY（必須レベル：高）

**用途**: Vercel AI Gateway。AIチャット・要約系などLLMを叩く処理すべてで使用。
未設定だとAI機能が一切動かない。

**取得手順**:
1. <https://vercel.com> にログイン
2. ダッシュボード → 対象プロジェクト → Settings → AI Gateway
3. 「Create API Key」→ 名前を入力（例: `local-dev-<ユーザー名>`）
4. 生成された `vck_...` で始まるキーを `.env` の `AI_GATEWAY_API_KEY=` に貼る

**注意**: Vercelプロジェクトへの参加が必要。チームメンバーに招待依頼。

---

### 1.2 LANGFUSE_PUBLIC_KEY / LANGFUSE_SECRET_KEY（必須レベル：中）

**用途**: LLM呼び出しログ・プロンプトのバージョン管理。
未設定でも AI機能自体は動く（プロンプト管理ができないだけ）。

**取得手順**:
1. <https://cloud.langfuse.com> にログイン
2. 既存の組織/プロジェクトに参加（チームに招待依頼）
3. Settings → API Keys → 「Create new API Keys」
4. 以下を `.env` に貼る：
   - `LANGFUSE_PUBLIC_KEY=pk-lf-...`
   - `LANGFUSE_SECRET_KEY=sk-lf-...`
5. `LANGFUSE_BASE_URL=https://cloud.langfuse.com` はそのままでOK

---

### 1.3 CHAT_DAILY_COST_LIMIT_USD（任意）

1日あたりのAIチャットコスト上限（USD単位）。
ローカルなら `10` 程度で十分。

```
CHAT_DAILY_COST_LIMIT_USD=10
```

---

### 1.4 CLAUDE_CLI_PATH（任意）

Admin の AI情報収集機能で使用。Claude CLI へのパスを指定。

```bash
which claude
```

の結果を貼る。空のままでも PATH 上の `claude` を自動で探す。

---

### 1.5 REVALIDATE_SECRET（任意）

Web側のISRキャッシュをAdminから無効化するためのシークレット。
ローカルでは `dev-secret` 等の適当な文字列でOK。
本番は強いランダム文字列を使うこと。

```
REVALIDATE_SECRET=dev-secret
```

---

### 1.6 BASIC_AUTH_USER / BASIC_AUTH_PASSWORD（ローカル不要）

本番のWebサイトに掛けるBasic認証。ローカルでは空のままで無効化。

## 2. WSL2 + Docker Desktop 環境固有の注意点

### 2.1 WSL2 mirrored networking

Windows側 `%UserProfile%\.wslconfig` に以下を設定済み：

```ini
[wsl2]
networkingMode=mirrored
dnsTunneling=true
firewall=true
autoProxy=true
```

これにより `localhost:3001` `localhost:3002` 等で WSL 内サービスへ
Windows ブラウザから直接アクセス可能。

### 2.2 Supabase ローカルポートの調整

Hyper-V が Windows 上で `54378-54777` 等のポート範囲を動的予約しているため、
Supabase CLI のデフォルトポート（54421/54432/54429/54423/54424/54427）と
衝突してコンテナ起動に失敗する。

そこで本リポジトリでは `supabase/config.toml` のポートを `54100` 台に
シフト済み（コミット `a01b8b0`）：

| 用途      | デフォルト | 当リポジトリ |
|----------|-----------|-------------|
| API      | 54421     | 54121       |
| DB       | 54432     | 54132       |
| Pooler   | 54429     | 54129       |
| Studio   | 54423     | 54123       |
| Inbucket | 54424     | 54124       |
| Analytics| 54427     | 54127       |

### 2.3 アクセスURL

- web: <http://localhost:3002>
- admin: <http://localhost:3001>
- Supabase Studio: <http://localhost:54123>
- Inbucket（メールテスト）: <http://localhost:54124>

### 2.4 Docker Desktop と mirrored モードの相性問題

WSL を mirrored モードに切り替えた直後、または WSL 再起動後に、
Docker コンテナへの port-forward が「Empty reply from server」になる症状が
発生することがある。

対応：**Docker Desktop を再起動**（タスクトレイから右クリック → Restart）。

## 3. ローカル初期セットアップ手順（まとめ）

```bash
# 1. .env 作成
cp .env.example .env
# 必要なAPIキーを上記手順で取得して書き込む

# 2. 依存インストール
pnpm install --frozen-lockfile

# 3. Supabase ローカル起動
npx supabase start

# 4. マイグレーション + 型生成
pnpm db:migrate

# 5. シードデータ投入
pnpm seed
# admin@example.com / admin123456 でログイン可能

# 6. dev サーバー起動
pnpm dev
```

からフォークし、**北海道および道内基礎自治体（市町村）向け**の議会情報
プラットフォームとして再構築する方針。

### 4.2 リポジトリ構成

| 項目 | URL |
|------|-----|
| origin | <https://github.com/s-takahashi-hokkaido/mirai-gikai-hokkaido> |
| upstream | <https://github.com/bakumon1107/mirai-gikai-fukuoka-city> |
| 現行ブランチ | `fukuoka-city/develop` |

`upstream` は元リポジトリの更新を参照したい場合に使う。普段の作業は `origin` のみ。

## 5. CLAUDE.md ルールについての扱い

本リポジトリは**個人開発（ソロ開発）のフォーク**であるため、
CLAUDE.md に書かれている以下のルールは厳密適用しない場合がある：

- **worktree 必須**: 機能開発時は推奨だが、設定変更や軽微な修正は
  メインフォルダで直接作業してもよい
- **PR必須・Codexレビュー必須**: 個人判断で直接 `develop` へ push を
  許容する場合がある（ただし lint/typecheck/test は必ず通すこと）

ただし以下はソロ開発でも厳守：

- **push 前のローカル検証**: `pnpm lint && pnpm typecheck && pnpm test`
  を必ず通してから push
- **Secrets を含むファイルはコミットしない**: `.env` は `.gitignore` 済み
