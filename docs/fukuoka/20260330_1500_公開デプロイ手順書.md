# 公開デプロイ手順書

作成日: 2026-03-30
対象: みらい議会 福岡市版

---

## 概要

本書はみらい議会 福岡市版を本番環境に公開するための手順をまとめたものです。
外部サービスの登録・設定から Vercel デプロイ、クラウド Supabase への移行まで網羅します。

---

## 必要な外部サービス一覧

| サービス | 用途 | 無料枠 | 必須/任意 |
|----------|------|--------|-----------|
| [Supabase](https://supabase.com) | データベース・認証 | 500MB DB / 1GB Storage / 2プロジェクト | **必須** |
| [Vercel](https://vercel.com) | web・admin のホスティング | Hobby: 100GB帯域/月 | **必須** |
| [Vercel AI Gateway](https://vercel.com/docs/ai/ai-gateway) | AI チャット（GPT-4o 等） | 従量課金のみ | 必須（チャット使う場合） |
| [Langfuse](https://langfuse.com) | AIプロンプト管理・LLM監視 | Hobby: 無料 | 必須（チャット使う場合） |
| [Google Analytics](https://analytics.google.com) | アクセス解析 | 無料 | 任意 |

## STEP 1: Supabase クラウドプロジェクト作成

### 1-1. アカウント登録・プロジェクト作成

1. https://supabase.com にアクセスし、GitHub アカウントでサインアップ
2. 「New Project」をクリック
3. 設定値:
   - **Name**: `mirai-gikai-fukuoka`
   - **Database Password**: 安全なパスワードを生成・保管
   - **Region**: `Northeast Asia (Tokyo)` を選択
4. 「Create new project」をクリック（3〜5分かかる）

### 1-2. 接続情報の取得

プロジェクト作成後、以下の値を控える:

| 項目 | 場所 |
|------|------|
| Project URL | Settings > API > Project URL |
| anon key | Settings > API > Project API Keys > anon public |
| service_role key | Settings > API > Project API Keys > service_role (**秘密**) |
| Database password | 1-1 で設定したもの |

### 1-3. マイグレーションの適用

```bash
# ローカルの .env に本番Supabaseの接続情報を一時的にセット（または別ファイルで管理）
# SUPABASE_URL=https://xxxx.supabase.co
# SUPABASE_SERVICE_ROLE_KEY=eyJ...

# マイグレーションを本番DBに適用
npx supabase db push --db-url "postgresql://postgres.<project-ref>:<password>@aws-0-ap-northeast-1.pooler.supabase.com:6543/postgres"
```

または Supabase ダッシュボード > SQL Editor から `supabase/migrations/` 配下の `.sql` ファイルを順番に実行。

### 1-4. 初期データの投入

```bash
# .env の SUPABASE_URL / SUPABASE_SERVICE_ROLE_KEY を本番に向けた状態で実行
pnpm seed                          # 管理ユーザー作成
pnpm --filter @mirai-gikai/seed budget:import   # 予算概要データ投入
pnpm --filter @mirai-gikai/seed budget:publish  # 全局を公開状態に
```

議案データは管理画面（admin）から公開操作を行う。

## STEP 2: Langfuse プロジェクト作成（チャット機能を使う場合）

### 2-1. アカウント登録

1. https://cloud.langfuse.com にアクセスし、サインアップ
2. 新しい Organization と Project を作成
   - **Project Name**: `mirai-gikai-fukuoka`

### 2-2. API キーの取得

Settings > API Keys から以下を取得:
- `LANGFUSE_PUBLIC_KEY`: `pk-lf-...`
- `LANGFUSE_SECRET_KEY`: `sk-lf-...`

### 2-3. プロンプトの登録

チャット機能が使用するプロンプトを Langfuse に登録する。
川崎版プロジェクトで使用中のプロンプトを流用する場合は、以下の名前で `production` ラベルをつけて登録:

| プロンプト名 | 用途 |
|-------------|------|
| `top-chat-system` | トップページのチャット |
| `bill-chat-system-normal` | 議案詳細チャット（通常モード） |
| `bill-chat-system-hard` | 議案詳細チャット（ハードモード） |

> **Note**: 予算概要チャット（`budget-chat-system`）はインラインプロンプトのため Langfuse 登録不要。

## STEP 3: Vercel AI Gateway 設定（チャット機能を使う場合）

### 3-1. Vercel AI Gateway の有効化

1. Vercel ダッシュボード > プロジェクト > AI タブ
2. AI Gateway を有効化
3. **API Key** を発行 → `AI_GATEWAY_API_KEY` として保管

> **Note**: AI Gateway は従量課金。GPT-4o の料金 ($2.50/1M input tokens, $10/1M output tokens) + Vercel のマークアップがかかる。
> `CHAT_DAILY_COST_LIMIT_USD` で一日あたりの上限を設定することを推奨（例: `1.0`）。

---

## STEP 4: Vercel プロジェクト作成・デプロイ

### 4-1. Vercel アカウント登録

1. https://vercel.com にアクセスし、GitHub アカウントでサインアップ

### 4-2. Web プロジェクトのデプロイ

1. Vercel ダッシュボード > 「Add New... > Project」
2. GitHub リポジトリ `mirai-gikai-fukuoka-city` をインポート
3. 設定:
   - **Framework Preset**: `Next.js`
   - **Root Directory**: `web`
   - **Branch**: `develop`
4. 環境変数を設定（下記「環境変数一覧」参照）
5. 「Deploy」をクリック

### 4-3. Admin プロジェクトのデプロイ

1. 同じリポジトリで2つ目のプロジェクトを作成
2. 設定:
   - **Framework Preset**: `Next.js`
   - **Root Directory**: `admin`
   - **Branch**: `develop`
3. 環境変数を設定
4. 「Deploy」をクリック

### 4-4. デプロイ後の URL 確認・相互設定

デプロイ後に発行された URL を環境変数に反映してから**再デプロイ**する:

| 変数 | 設定するプロジェクト | 値 |
|------|------------|-----|
| `NEXT_PUBLIC_WEB_URL` | admin | `https://mirai-gikai-fukuoka.vercel.app`（web の URL） |
| `ADMIN_URL` | web | admin の URL |

## STEP 6: 管理者ユーザーの作成

本番 Supabase ダッシュボードで以下を実行:

1. Authentication > Users > 「Add user」でメールアドレス・パスワードを登録
2. SQL Editor で管理者権限を付与:

```sql
UPDATE auth.users
SET raw_app_meta_data = raw_app_meta_data || '{"roles": ["admin"]}'::jsonb
WHERE email = '作成したメールアドレス';
```

## 公開前に対処が必要な既知の問題

### 🔴 重要度：高（公開前に必ず対応）

#### 1. `tmp_*.pdf` が Git に含まれている

**問題**: 開発時のサンプル PDF（`tmp_giin.pdf` など5ファイル、計約700KB）がリポジトリに追跡されている。Git リポジトリを公開する場合、これらのファイルが公開される。

**対処**:
```bash
git rm tmp_giin.pdf tmp_giin2.pdf tmp_ikensho.pdf tmp_seigan.pdf tmp_voting.pdf
git commit -m "chore: 開発用一時PDFファイルを削除"
```
また `.gitignore` に `tmp_*.pdf` を追加しておく。

---

#### 2. OGP 画像が川崎版のまま

**問題**: `web/public/ogp.jpg` が川崎版のデザインのまま。SNS シェア時に川崎版の画像が表示される。

**対処**: 福岡市版用の OGP 画像（1200×630px 推奨）を作成し `web/public/ogp.jpg` を差し替える。

---

#### 3. `aiInterview` 機能が有効になっている

**問題**: `siteConfig.features.aiInterview = true` だが、福岡市版では AI インタビュー機能のデータ（interview_configs）が未整備。有効のまま公開すると、存在しないインタビュー機能への導線が表示される可能性がある。

**対処**: 準備ができるまで `web/src/config/site.config.ts` で無効化:
```ts
aiInterview: false,
```

---

### 🟡 重要度：中（公開後でも対応可）

#### 4. コード中に「川崎」のコメントが残っている

**問題**: 以下のファイルにコメントとして川崎市議会の記述が残っている（表示には影響しないが、リポジトリ公開時に混乱を招く）:

| ファイル | 内容 |
|----------|------|
| `web/src/features/bills/shared/utils/bill-progress.ts` | 「川崎市議会: 一院制」のコメント |
| `web/src/features/bills/client/components/bill-detail/bill-status-progress.tsx` | 同上 |
| `web/src/features/bills/server/repositories/bill-repository.ts` | 「川崎市議会DBには...」のコメント |

**対処**: 各ファイルのコメントを「福岡市議会」または汎用表現に書き換える。

---

#### 5. `councilBaseUrl` / `councilBillsDetailUrl` のリンク先確認

**問題**: `site.config.ts` に設定している議会 URL が正しく機能しているか本番環境で確認が必要。

**対処**: デプロイ後に「すべての議案は福岡市議会情報へ」リンクが正しく遷移するか確認する。

---

#### 6. PWA アイコンが川崎版のデザインのまま

**問題**: `web/public/icons/pwa/` の PWA アイコンが川崎版デザインのまま。ホーム画面追加時に川崎版アイコンが表示される。

**対処**: 福岡市版用のアイコン画像に差し替える（192×192, 512×512, iOS用 各 PNG）。
