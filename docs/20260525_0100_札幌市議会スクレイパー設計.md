# 札幌市議会スクレイパー設計

## 概要

札幌市議会の公式サイトから議案データ・会議録を自動取得し、DB投入 + AI解説生成まで行うスクリプト群を `packages/seed/sapporo/` に構築する。

福岡版（upstream）の `packages/seed/fukuoka/` を参考に、札幌市議会のサイト構造に合わせて新規実装する。

**初回対象スコープ**: 令和8年第2回定例会のみ（議案20件 + 諮問1件）

## データソース

### 1. 議案一覧（HTMLテーブル）

- URL: `https://www.city.sapporo.jp/gikai/html/giantouichiran.html`
- エンコーディング: UTF-8
- 形式: HTMLテーブル（種別ごとに分割: 議案/諮問/陳情/報告）
- 過去の定例会: `giantouichiran0801t.html` 等のパターンで遡れる

取得可能な情報:

| カラム | 例 |
|--------|-----|
| 番号 | 議案第1号 |
| 件名（PDFリンク付き） | 令和8年度札幌市一般会計補正予算（第1号） |
| 本会議提出日 | 令和8年5月21日 |
| 議決日 | （未議決の場合は空欄） |
| 結果 | 原案可決 / 否決 / 空欄 |

### 2. 会議録検索システム（gijiroku.com）

- URL: `https://sapporo.gijiroku.com/voices/`
- エンコーディング: **Shift_JIS**
- 形式: voiweb.exe CGI経由のHTML

サイト構造:
```
会議一覧（ACT=100） → フレームセット（ACT=200）
  ├── サイドバー 発言者一覧（ACT=202）
  └── 本文（ACT=203）  ← これを取得する
```

主要なCGIパラメータ:

| パラメータ | 用途 | 例 |
|-----------|------|-----|
| `ACT=100` | 会議一覧取得 | `&KGTP=1&FYY=2026&TYY=2026` |
| `ACT=203` | 会議録本文取得 | `&FINO={ファイルID}&HUID={発言ID}` |
| `KGTP=1` | 本会議 | `KGTP=2` で委員会 |
| `FYY` / `TYY` | 対象年（西暦） | `FYY=2026&TYY=2026` |

### 3. 速報版（委員会のみ）

- URL: `https://www.city.sapporo.jp/gikai/html/kaigiroku-sokuho.html`
- 形式: PDF
- **本会議の速報版は存在しない**（委員会の会議録PDFのみ掲載）
- 今回のスコープ外。将来的に委員会の質疑を取り込む場合に利用

## 会議録フォーマット調査結果

### 発言者マーカー

札幌版は記号で発言者の役割が区別できる（福岡版は全て同じ記号 `◯`）。

```
┌──────┬────────────────────────────────┬──────────────────────┐
│ 記号 │          札幌版の意味          │     福岡版の対応     │
├──────┼────────────────────────────────┼──────────────────────┤
│ ○    │ 議長・副議長                   │ ◯議長（...）         │
├──────┼────────────────────────────────┼──────────────────────┤
│ ◆    │ 質問者（議員）                 │ ◯57番（田中たかし）  │
├──────┼────────────────────────────────┼──────────────────────┤
│ ◎    │ 答弁者（市長・副市長・局長等） │ ◯農林水産局長（...） │
└──────┴────────────────────────────────┴──────────────────────┘
```

具体例（実際の会議録から）:
```
○議長（長内直也）　答弁を求めます。
◆山田一郎議員　私は、自由民主党議員会を代表し、...質問させていただきます。
◎市長（秋元克広）　全体で９項目にわたり、ご質問いただきました。...
◎副市長（天野周治）　私からは、大きな７項目め、...
◎教育長（山根直樹）　私からは、６項目めの...
◎総務局長（中澤伸之）　...
```

### 福岡版との主な違い

| 項目 | 福岡版 | 札幌版 |
|------|--------|--------|
| 記号の使い分け | 全て `◯`、パターンで判別 | `◆` `◎` `○` で役割区別 |
| 質問者の形式 | `◯57番（田中たかし）登壇` | `◆山田一郎議員` |
| 議席番号 | あり | なし |
| 答弁者の形式 | `◯農林水産局長（姉川雄一）` | `◎総務局長（中澤伸之）` |
| 副議長 | （未確認） | `○副議長（村上ゆうこ）` |

### 質問種別

- 2024年の全定例会を確認したところ、札幌市議会は**代表質問のみ**（一般質問は未確認）
- 会議一覧ページ（ACT=100）には「代表質問」「一般質問」の区分はない
- 会議録本文の中で `代表質問` というラベルが質問セクションの前に単独行で挿入されている
- 「〇〇を代表し」という発言文言からも判別可能

### 会議録の日程パターン

```
01号 — 開会日（議案提出、提案説明、委員会付託）→ 質疑なし
02号〜 — 代表質問（質疑応答あり）← パース対象
最終号 — 委員長報告、討論、採決 → 議決結果の更新に利用可能
```

## 設計

### ディレクトリ構成

```
packages/seed/sapporo/
├── types.ts                     # 共有型定義（ScrapedBill, SpeechBlock, DiscussionGroup）
├── config.ts                    # 定例会メタデータ（URL、slug等）
├── fetcher.ts                   # HTTP取得ユーティリティ（Shift_JIS対応、リトライ、レート制限）
├── parse-bill-table.ts          # 純粋関数: 議案一覧HTML → ScrapedBill[]
├── parse-bill-table.test.ts
├── parse-minutes.ts             # 純粋関数: 会議録HTML → SpeechBlock[]
├── parse-minutes.test.ts
├── scrape-bills.ts              # Step 1: 議案一覧 → bills テーブル
├── scrape-minutes.ts            # Step 2: 会議録 → bill_discussions テーブル
└── generate-bill-contents.ts    # Step 3: AI → bill_contents テーブル
```

### 処理フロー

```
Step 1: scrape-bills
  議案一覧HTML取得 → parse-bill-table → bills upsert

Step 2: scrape-minutes（Step 1 完了後に実行）
  会議録一覧取得 → 02号〜をフィルタ → 本文取得
  → parse-minutes → groupIntoDiscussions
  → Claude CLI で AI要約 → bill_discussions upsert

Step 3: generate-bill-contents（Step 1 完了後に実行）
  DB から未生成の bills 取得
  → Claude CLI で normal/hard の解説文生成
  → bill_contents upsert
```

### Phase 1: 議案一覧の取り込み

**基盤** (`types.ts`, `config.ts`, `fetcher.ts`)

- `fetcher.ts`: `TextDecoder("shift_jis")` でShift_JIS対応（Node.js 22で動作確認済み）。リトライ（3回、指数バックオフ）とレート制限（1秒間隔）を内蔵。`fetch` ベースで追加パッケージ不要

**議案HTMLパーサー** (`parse-bill-table.ts`)

- 入力: `giantouichiran.html` のHTML文字列
- HTMLテーブルを正規表現でパース（種別ごとにテーブルが分かれている）
- 報告はスキップ（議案ではないため）

結果 → status マッピング:

| 結果カラム | bills.status |
|-----------|-------------|
| 原案可決 / 同意 / 承認 | `approved` |
| 否決 | `rejected` |
| 空欄（未議決） | `submitted` |

**議案スクレイパー** (`scrape-bills.ts`)

- `giantouichiran.html` をフェッチ → パース → `bills` テーブルに upsert
- `council_session_id` は slug `r8-2` で検索（`packages/seed/main/data.ts` で定義済み）
- upsert キー: `(council_session_id, bill_number, bill_type)`
- `source_url` に議案PDFのフルURLを設定

### Phase 2: 会議録の取り込み

**会議録パーサー** (`parse-minutes.ts`)

福岡版 `fukuoka/parse-minutes.ts` の構造（型定義・関数構成）を流用し、正規表現を差し替え:

```typescript
// 質問者: ◆山田一郎議員
const QUESTIONER_LINE_RE = /^◆(.+?議員)/;
// 答弁者: ◎市長（秋元克広） / ◎副市長（天野周治） / ◎総務局長（中澤伸之）
const ANSWERER_LINE_RE = /^◎(.+?)（(.+?)）/;
// 議長: ○議長（長内直也） / ○副議長（村上ゆうこ）
const CHAIRPERSON_LINE_RE = /^○(?:議長|副議長)（/;
// 質問種別ラベル: 本文中に「代表質問」が単独行で出現
const QUESTION_TYPE_RE = /^代表質問$/;
```

福岡版から再利用する関数:
- `extractBillNumbers` — 「議案第N号」パターン抽出（同一ロジック）
- `countExchanges` — 質問→答弁の往復カウント（同一ロジック）
- `extractParty` — 正規表現を札幌の会派名に変更（「自由民主党議員会」「民主市民連合」等）

**会議録スクレイパー** (`scrape-minutes.ts`)

- gijiroku.com CGI API で会議録一覧取得 → 02号以降をフィルタ
- 会議一覧に「代表質問」の区分はないため、本文中の `代表質問` ラベルで種別を判定
- HTML → テキスト変換（`<BR>` → `\n`、タグ除去）→ パース → AI要約 → DB投入
- Claude CLI で要約生成（福岡版 `callClaude` / `buildSummaryPrompt` パターン踏襲）
- 複数答弁者は `answerer_role` に「○○局長（氏名）・市長（氏名）」形式で格納

### Phase 3: AI解説生成

**`generate-bill-contents.ts`**

- DB から未生成の bills を取得
- 議案名 + カテゴリから Claude CLI で normal/hard の2バリアント生成
  - normal: 市民向け（わかりやすい日本語、専門用語の補足付き）
  - hard: 条文・財政分析（法的根拠、数値の詳細）
- CLAUDE.md の「AI生成コンテンツ確認ルール」に従い、**デフォルトはドライラン**（`--confirm` で実投入）
- 品質チェック: 中国語簡体字混入、日本語の自然さ
- PDF テキスト抽出は将来対応（今回は議案名のみで生成）

### ドライラン

全スクリプトに `--dry-run` フラグを実装:
- `scrape-bills` / `scrape-minutes`: `--dry-run` でDB投入をスキップ、パース結果のみ出力
- `generate-bill-contents`: **デフォルトがドライラン**、`--confirm` で実投入

## DBマッピング

### bills テーブル

| サイトから取得 | DBカラム | 備考 |
|---------------|---------|------|
| 番号（議案第1号〜） | `bill_number` | テキスト型 |
| 件名 | `name` | |
| 本会議提出日 | `published_at` | ISO 8601 |
| 議決日 + 結果 | `status` / `status_note` | マッピング表参照 |
| PDFリンク | `source_url` | 絶対URLに変換 |
| 種別（議案/諮問） | `bill_type` | `bill` 固定（諮問も通常議案扱い） |
| — | `council_session_id` | slug `r8-2` で検索 |
| — | `publish_status` | `published` |

### bill_discussions テーブル

| パースから取得 | DBカラム | 備考 |
|---------------|---------|------|
| 質問者名 | `questioner_name` | 「議員」サフィックスを除去 |
| — | `questioner_number` | null（札幌は議席番号なし） |
| 会派名 | `questioner_party` | `extractParty` で抽出 |
| 質問テキスト | `question_raw` | |
| AI要約 | `question_summary` | Claude CLI で生成 |
| 答弁者役職 | `answerer_role` | 複数の場合は連結 |
| 答弁者名 | `answerer_name` | |
| 答弁テキスト | `answer_raw` | |
| AI要約 | `answer_summary` | Claude CLI で生成 |
| 往復回数 | `exchange_count` | `countExchanges` で算出 |

## 検証方法

1. `pnpm --filter @mirai-gikai/seed test` でパーサーのユニットテスト通過
2. `scrape:bills -- --dry-run` で議案20件のパース結果を目視確認
3. ローカル Supabase で `scrape:bills` を実行 → Admin UI で議案が表示されることを確認
4. `scrape:minutes -- --dry-run` で質疑グループ数・AI要約を目視確認
5. `generate:bill-contents -- --dry-run` で normal/hard の解説文を目視確認
6. `pnpm lint && pnpm typecheck` 通過
